# KPAR Import Design Contract

This document is the committed output of completion-roadmap **Phase 3a**. It
decides the semantics of importing OMG KPAR content into Gaphor *before* any
importer materializes model state, so identity, storage, read-only treatment,
dependency, partial-import, and provenance policy are chosen deliberately rather
than accidentally.

It governs the import phases that follow:

- **Phase 3b** -- minimal normative-library import (the KerML value types needed
  for `attribute x : Real`).
- **Phase 3c** -- general user KPAR import.

The four headline decisions were ratified at the Phase 3a review gate:
ElementFactory-backed read-only library elements regenerated on load;
subset-import with explicit unresolved/diagnostic records; a Python-API-only
entry surface for 3b; and a closed-world dependency policy over the pinned
artifacts.

## Status And Scope

This is **design-only**. **No importer code, no ElementFactory mutation, and no
imported semantic content** land in Phase 3a, and **no support-matrix cell
moves**. The pinned baseline is the OMG 20250201 artifacts under
`docs/sysml-v2/omg/20250201/` (see that directory's manifest and the Phase 1/2
work). The read-only KPAR reader (`gaphor/SysML2/kpar/`) is the substrate the
importer will build on; this contract does not change it.

Claim discipline still holds: Phase 3b may only claim value-type resolution once
its focused tests pass.

## Identity

- Gaphor `Base.id` stays **Gaphor-internal**. It is generated by the importer
  for materialized elements and is *not* the KPAR identity, the source element
  id, or any SysML v2 API id. (This preserves the kickoff invariant that
  Gaphor's internal ids stay distinct from API-facing ids.)
- The **canonical identity** of an imported library element is its
  fully-qualified KerML name (for example `ScalarValues::Real`) together with its
  KPAR provenance. Resolution and lookup are by qualified name, not by `Base.id`.
- No API-facing identity is minted in Phase 3a/3b. Any API id alignment is
  deferred to Phase 13 and must not be assumed by the importer.

## Storage

- Imported normative-library elements are **not persisted into the user's
  `.gaphor`** file. The pinned KPAR bytes remain the single source of truth.
- Library elements live in a **dedicated read-only library ElementFactory that is
  regenerated from the pinned KPAR on load**. A user model references library
  types by qualified name plus provenance; it does not carry its own copy of the
  normative content.
- Rationale: no hand-authored or duplicated value-type stubs; normative content
  cannot silently diverge from the pinned source; models stay lean.
- Consequence (documented, accepted): a `.gaphor` model that references library
  types is only fully resolvable when the matching pinned KPAR is present.
  General user KPAR import (Phase 3c) may revisit storage for *user* content, but
  the normative-library treatment defined here is the default.

## Representation

- Imported library content is materialized as **real KerML kernel elements**
  (`DataType`, `Package`, the relevant generalization/specialization edges, etc.)
  created through the existing kernel Create-API. This honours the invariant that
  SysML v2 / library content is built on the KerML kernel, never on ad-hoc
  parallel structures.
- The importer parses KPAR `.kerml`/`.sysml` declarations into those kernel
  elements; it does not invent a separate non-kernel value-type model.
- The chosen value-type slice for Phase 3b is the `ScalarValues` package
  (`Boolean`, `String`, `NumericalValue`, `Number`, `Complex`, `Real`,
  `Rational`, `Integer`, `Natural`, `Positive`) and its owning package.

## Mutability And Read-Only Treatment

- Normative OMG libraries are **read-only**. The library factory is not exposed
  for user editing, and no UI create/edit/delete surface is offered on library
  elements.
- Because library elements are regenerated from pinned bytes on load, any
  in-memory change would be discarded; the contract makes that an explicit
  read-only guarantee rather than an accident of regeneration.
- User KPAR imports (Phase 3c) may become editable only under an explicit,
  separately reviewed policy. Until then, all KPAR-imported content is read-only.

## Dependency Closure

- The normative-library importer is **closed-world over
  `docs/sysml-v2/omg/20250201`**. It **never fetches** dependencies over the
  network or from outside the pinned set.
- It resolves `.project.json` `usage` entries **only to pinned artifacts**.
- Phase 3b imports the **minimal dependency closure** needed by the targeted
  declarations -- not the full transitive closure of every `usage` edge.
- If a required `usage` dependency **cannot be matched to a pinned KPAR, the
  import fails with a diagnostic** (a missing required dependency is an error,
  never a silent omission).
- Unsupported or unresolved model references *inside an otherwise available
  dependency* are recorded explicitly (see Unsupported Syntax And Partial
  Import), not treated as a hard dependency failure.
- Import order follows dependency order so a dependency is materialized before
  the elements that reference it.

## Duplicate, Re-Import, And Update

- Import is **idempotent**: re-importing the same pinned KPAR (matched by its
  manifest SHA-256 and the qualified names it defines) yields the same library
  state, not duplicate elements.
- A KPAR whose bytes or version do not match the Phase 1 pinned manifest is an
  **error** -- provenance must trace to the pinned artifact set.
- A library qualified name that collides with an existing user element is a
  **diagnostic/error, never a silent overwrite** of either side.
- Picking up a newer OMG release is a deliberate manifest update (Phase 1 / the
  spec-ingestion pipeline), not an implicit import-time upgrade.

## Unsupported Syntax And Partial Import

- The importer **never silently drops** content (per
  `docs/sysml-v2/CONFORMANCE_POLICY.md`).
- It imports the **supported declaration subset** and records **every**
  unsupported construct and **every** unresolved or cross-library reference (for
  example `Base::DataValue` when `Base` is outside the imported closure) as an
  **explicit unresolved/proxy record carrying a diagnostic**.
- An import that produced unresolved records still **succeeds with a diagnostics
  report**, unless a *required* dependency is missing or a structural
  precondition fails -- those are errors.
- `ERROR` vs `WARNING` severity follows the conformance policy: `ERROR` when the
  content cannot be understood enough to preserve or reference safely; `WARNING`
  only when it is preserved/recorded losslessly with a tracked reference.

## Provenance

- Every imported element and every recorded reference traces to a **pinned KPAR
  entry**. No imported element exists without provenance.
- Recorded provenance includes: the KPAR archive path, its pinned **SHA-256**,
  the **member file**, the **source declaration text**, and the **declaration
  span (line)** when available.
- Provenance is what makes Phase 3b's "no hand-authored stubs" claim verifiable:
  a test can confirm each imported value type's source text actually appears in
  the pinned member it claims to come from.

## Entry-Point Boundary

- Phase 3b exposes a **Python API only**: import a pinned normative library, and
  resolve a qualified value-type name to its imported kernel element plus
  provenance. No CLI and no UI import entry point ships in 3b.
- The existing read-only `sysml2-kpar-info` command stays inspection-only; it
  does not gain import behavior in 3b.
- CLI and UI import entry points are deferred to **Phase 3c** ("if appropriate
  for Gaphor's import flow").

## Verification

- Phase 3a (this phase) is anchored by a design-contract consistency check
  (`gaphor/SysML2/tests/test_kpar_import_contract.py`) plus the always-on project
  gates, including a static gate that this document exists. No behaviour test and
  no support claim are added, because no importer exists yet.
- Phase 3b will add focused import, provenance, and read-only-library tests and
  run the full SysML2 subset before any value-type resolution claim, per
  `VERIFY.md`.
